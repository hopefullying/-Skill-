## I — 方法论骨架 (Interpretation)

这套语料里，时间不是背景，是**变量**。做法分四层：

1. **标日历**：把相关方的选举日、换届日、财政节点、库存耗尽日列成一张时间表。
   凡"必须在自己窗口内拿到结果"的一方，窗口关闭前一定出现动作。
2. **分节奏**：问"是谁在决定打击的频率和议题？"。被迫应对、被迫加码的一方，
   就算资源更多也在失去主动权；主动权 + 结束权 = 真正的战略胜利。
3. **把谈判当消耗**：谈判不只是分条款，谈判期本身就是对时间压力大的一方的持续放血。
   反复多轮仍无定论，说明双方都不是在解决问题，而是在等时机。
4. **拖与不拖的判据**：
   - 弱势方 → 优先把战争拖长（时间越长，外援、调停、政治操作的空间越大）；
   - 强势方 → 最怕被拖（维持成本随时间线性烧钱，撤走即等于承认失败）；
   - 但"拖"有反时限：对手也在武装/整合，等到对手准备好，窗口就没了。

关键断言：**谁等不了，谁先崩**——所以"拖"本身就是武器。

## A1 — 语料中的应用 (Past Application)

### 案例 1：中东的两条时间表（2026-8-1）
- **问题**：这场战争会拖到什么时候？
- **用法**：标日历——8 月是伊朗的最佳窗口；10 月以色列大选、11 月美国中期选举是美方的硬节点。
- **结论**：窗口一过，双方都被自己的政治日历逼着做动作，而不是按战场最优做动作。

### 案例 2：三艘航母的成本账（2026-5-2）
- **问题**：美国是虚张声势还是真要打？
- **用法**：算维持成本——三艘航母同场部署，日均开销极大，长期不打就只能撤。
- **结论**：撤离本身是"意志衰减"的可读信号，比口头表态可靠。

### 案例 3：谈判变成消耗战（2026-4-28 / 2026-6-11）
- **问题**：伊朗为什么迟迟不签？
- **用法**：把谈判期计入消耗——对方内部政治时间压力更大，拖长谈判比多打一轮更难受。
- **结论**：谈判是第二条战线，不是战争的替代品。

## A2 — 触发场景 (Appropriation)

出现下列问题时调用：
- "这仗/这事接下来什么时候会升级？"
- "谈判谈了这么多轮，为什么还没结果？"
- "谁占上风——是打得多的一方，还是能决定什么时候停的一方？"
- "现在不动手是不是就错过窗口了？"

---

## E — 可执行步骤 (Execution)

1. **建时间表**：列出各方硬节点（选举、换届、财年、库存/资源耗尽日、停火协议到期日），标出"必须在 X 前拿到结果"的一方。
2. **判节奏归属**：看谁在设定动作频率与议题；被迫应对、被迫加码的一方 = 节奏已失。
3. **算维持成本**：高成本兵力/制裁/援助每天烧多少；"长期不动又突然撤"= 意志衰减信号。
4. **判谈判性质**：轮次多、条件反复加 = 拖延战术，不是在解决问题；把谈判期按消耗战计算。
5. **给窗口**：输出"下一个动作窗口在 X 前后 + 触发条件是什么"。
6. **加反时限**：明确"拖到什么时候就不能再拖了"（对手完成武装/整合的时点）。

---

## B — 边界与失效条件 (Boundary)

- **不要用于高频预测**：这套方法给的是"窗口 + 触发条件"，不是精确日期。语料里多次出现时间点顺延。
- **反时限必须写出来**：他自己给了反例——对手也在武装与整合，等对手准备好，窗口就关闭了（出处：2026-4-11）。也就是说"拖"并非永远有利。
- **决策者不稳定时失效**：面对"一天一个样、不按剧本走"的对手，基于连续战略逻辑的时间推演会失灵（见 `causal-chain-consistency`）。
- **不要把"拖"当成被动**：在这套体系里，拖是主动选择，前提是自己能承受消耗且对手更不能承受。
